# モデル戦略：ローカルモデル + API の併用

## 考え方

| 観点 | ローカル LLM | API モデル |
|---|---|---|
| コスト | 電気代のみ（定期処理向き） | 従量課金 |
| 機密性 | データが外に出ない | ログ等を外部送信することになる |
| 性能 | 軽量・定型処理は十分 | 複雑な推論・長文解析に強い |
| 可用性 | ネット断でも動く | ネット・API 障害の影響を受ける |
| 応答速度 | ハードウェア次第 | 安定して速いことが多い |

## 振り分けルール（たたき台）

**ローカルで処理**
- ログの定型分類・要約（大量・定期）
- 簡単な質問（「ディスク残量は？」など、ツール結果をそのまま整形する系）
- 機密情報（認証ログ、内部 IP、ユーザー名など）を含む処理
- API が使えないときのフォールバック

**API に送る**
- 障害の原因推定など多段の推論が必要なもの
- アップデートの影響分析（変更履歴・既知の不具合の読み込み）
- ローカルモデルの出力の自信度が低いとき（エスカレーション）

## 検討事項

- **マスキング**：API に送る前に IP・ホスト名・ユーザー名・秘密情報を置換する仕組み
- **エスカレーション基準**：ローカル → API へ切り替える条件（自信度、タスク種別、失敗回数）
- **コスト上限**：月間・日次の API 予算と、超過時の挙動
- **ローカル推論基盤**：Ollama / llama.cpp / vLLM などから選定（未決）
- **ハードウェア**：GPU の有無で使えるモデルサイズが変わる
- **評価**：同じ質問に対するローカルと API の回答を比較する仕組み
