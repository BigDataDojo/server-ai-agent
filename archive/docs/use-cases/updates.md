# ユースケース：カーネル・パッケージ・モジュールのアップデート

## 対象
- OS パッケージ（apt / dnf など）
- カーネル本体
- カーネルモジュール（DKMS で管理するもの：GPU ドライバ、ZFS など）
- （将来）コンテナイメージ、言語ランタイム

## 想定フロー

```
1. 検出   更新可能なものを一覧化
2. 分析   変更内容・セキュリティ重要度・既知の不具合・依存関係を調査
3. 計画   実行手順・再起動の要否・ロールバック方法を提示
4. 承認   人間が確認して OK を出す        ← 必須
5. 退避   スナップショット / 現行カーネルの保持 / 設定バックアップ
6. 実行   メンテナンス時間帯に適用
7. 検証   再起動後の起動確認・モジュールのロード確認・サービス疎通
8. 報告   結果をログに記録して通知。失敗時はロールバック手順を提示
```

## 特に注意すること
- **カーネル更新と DKMS モジュールの整合性**：新カーネル向けにモジュールがビルドできるか事前に確認
- **再起動が必要か**：needrestart 等で影響サービスを把握
- **起動不能リスク**：旧カーネルを GRUB に残す、リモートから復旧手段（IPMI 等）があるか
- **段階適用**：複数台あるなら 1 台で検証してから展開

## 権限レベル案
| レベル | 内容 |
|---|---|
| 0 | 更新の検出と報告のみ |
| 1 | 計画まで作成、実行は人間 |
| 2 | 承認後にエージェントが実行 |
| 3 | セキュリティ更新のみ自動適用（再起動なしに限る） |
