# ユースケース：質問対応・トラブル対応

## 質問対応（Q&A）
自然言語の質問に、**実際にサーバーを調べて**答える。

例：
- 「ディスクが一番食われてるディレクトリは？」
- 「昨日の夜に再起動した？」
- 「nginx のエラーが増えてるのはいつから？」
- 「このサーバーで動いてるサービスを一覧にして」

ポイント：
- 推測ではなく、ツール実行結果に基づいて答える（根拠のコマンドと出力を添える）
- 読み取り専用コマンドだけで答えられる質問は承認なしで実行してよい（要検討）

## トラブル対応（一次切り分け）
アラートや人間からの報告をきっかけに調査を開始する。

想定フロー：
1. 症状の把握（何が・いつから・どの範囲で）
2. 情報収集（ログ、リソース使用率、直近の変更履歴、サービス状態）
3. 原因候補の列挙と根拠
4. 対処案の提示（リスクと戻し方つき）
5. 承認された対処のみ実行
6. 事後レポート（ポストモーテムの下書き）を作成し、知識ベースへ蓄積

## アイデア
- 過去の障害事例を検索して「前にも似たことがあった」を提示
- 手順書（runbook）を Markdown で置いておき、エージェントが参照・実行
- 解決できない場合のエスカレーション先（人間への通知方法）
