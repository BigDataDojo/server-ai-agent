# 研究室のインフラ（現状）

## 役割

エージェントが動く場所と、エージェントが調査・操作する対象。この章は「いまどうなっているか」の記録で、変えたら末尾の改善ログに1行足す。

> IP アドレス、ドメイン、経路の細かい設定はここに書かない。元資料「ops-agent 接続構成」を参照する。

## 現在の構成

### ネットワーク

研究室のサーバーは Cloudflare を通してつながっている。エージェントからサーバーへの通信は、LAN の中で直接つながず、必ず Cloudflare One を通す。そこで本人確認と記録をするためである。

| 構成要素 | 役割 |
| --- | --- |
| fsm01 | 研究室 LAN の出入口。ゲートウェイ・DNS・インターネットへの出口 |
| fsm02 | Proxmox のサーバー。LXC 101 が Cloudflare への入口、LXC 120 がエージェント、LXC 121 が承認後の操作役 |
| Cloudflare One | 通信は必ずここを通る。ID を確認し、SSH の短期証明書を出し、コマンドを記録する |
| octa / deca | 別拠点のサーバー。octa の WARP Connector を通って届く |

### Proxmox（fsm02）

1台の物理サーバーの中に、LXC という軽い仮想マシンをいくつも作り、サービスごとに分けて動かしている。新しいサービスを立てる＝新しい LXC を作る。

| LXC | 名前 | 役割 |
| --- | --- | --- |
| 101 | cloudflared | Cloudflare への入口 |
| 102 | bitwarden | 研究室のパスワード管理 |
| 120 | ops-agent | このプロジェクトのエージェントが住む箱（作成済み） |
| 121 | — | 承認後の操作役 |

管理は Web UI と API（8006番）で行う。エージェントは API から箱の状態確認・起動・停止ができる。

### Cloudflare

外からの入口と本人確認をまとめて引き受けている。

| 機能 | 役割 |
| --- | --- |
| Tunnel | サーバー側から外向きに接続するだけ。学内ファイアウォールに受信ポートを開けなくてよい |
| Access（セルフホスト型） | 各 Web アプリの前に立ち、研究室メンバーだけを通す。研究室のサービスはすべて研究室のドメインのサブドメインで公開し、Access で本人確認してから通している |
| Access for Infrastructure（インフラストラクチャ型） | SSH に短期証明書を発行し、鍵を配らずにサーバーへ入れる。エージェントもこれで入るので、エージェントは SSH の鍵を持たない |
