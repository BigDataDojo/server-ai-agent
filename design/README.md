# 設計書

このフォルダが、このプロジェクトの設計書の本体。上から順に各フォルダの `README.md`（現在の構成）を読むと、1冊の設計書になる。

**ここに入るのは、MTG で採用が決まったものだけ。** 変更は必ず PR で出し、立ち上げメンバーのレビューを受けてからマージする（出し方は [project/process.md](../project/process.md)）。調べている途中のことは [`notes/`](../notes/) に書く。

## 各章の中身

どの章も、次の2種類のファイルでできている。

```
<章>/
├── README.md            # 現在の構成：いま採用されている設計。末尾に改善ログ
└── decisions/           # 決定記録：1つの決定につき1枚。採用も却下も残す
    └── YYYY-MM-DD-<短い名前>.md
```

- **`README.md`（現在の構成）** は「いまどうなっているか」だけを書く。決定がマージされたら、同じ PR でここも書き換え、末尾の改善ログに1行足す。
- **`decisions/`（決定記録）** は「なぜそうしたか」を残す。却下になった提案も、状態を「却下」にしてマージする。あとで同じ議論を繰り返さないため。
- ファイル名は連番ではなく日付で付ける。何人かが同時に PR を出しても番号がぶつからない。

テンプレートは [`templates/`](templates/) にある。

| テンプレート | 使うとき |
| --- | --- |
| [templates/decision.md](templates/decision.md) | 新しく決めたいことがあるとき（「今週の問い」の答え） |
| [templates/current.md](templates/current.md) | 新しい章やサブシステムを作るとき |
