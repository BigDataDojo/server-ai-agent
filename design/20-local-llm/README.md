# ローカルLLM エージェント（コース A）

## 役割

ドキュメントを検索し、根拠の場所を引用して問い合わせに答える。外部に送る前の機密情報の処理（マスキング）もここで行う。自分では答えられないと判断したら、その旨を返して Claude エージェントに引き継ぐ。

## 目標

過去の問い合わせの 7 割に、根拠ドキュメントを引用した正しい回答を返せる。Slack の質問チャンネルで動く状態にする（7 割は仮置き。Slack ログの残り具合を見て調整する）。

| 時期 | 節目 | 中身 |
| --- | --- | --- |
| 11月末 | 評価データ完成 | 過去の Slack 問い合わせ 30 件に「正解」「根拠の場所」「画像の有無」を付ける |
| 12月 | 設計書 v1 承認 | 検索方式、ドキュメント更新への追従、画像の扱いが決まっている |
| 1月 | 試作 | テストチャンネルで動く（人が確認してから投稿） |
| 2月〜 | 精度の測定 | 目標を超えたら本チャンネルで自動回答 |

## サブシステム

4つのサブコースに分かれ、各2〜3人で担当する。

| サブシステム | やること | 状態 |
| --- | --- | --- |
| [① 評価データ](1-eval-data/) | 過去の問い合わせと正解をまとめる | 未着手 |
| [② 検索](2-retrieval/) | ドキュメントから該当箇所を見つける | 未着手 |
| [③ 回答生成](3-generation/) | 見つけた箇所を元に回答を作る | 未着手 |
| [④ Slack 連携と評価](4-slack-eval/) | Slack で動かし、精度を測る | 未着手 |

①は技術がなくても今すぐ始められ、全体の土台になる。評価データがないと、作ったものが良いのか悪いのか判断できない。
