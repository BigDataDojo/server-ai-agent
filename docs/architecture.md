# 全体構成案

> まだ案の段階。採用が決まったものは [ADR](adr/) に記録する。

## コンポーネント

```
          ┌──────────────┐
  人間 ⇄ │ インターフェース │  CLI / チャット(Slack, Discord 等) / Web UI
          └──────┬───────┘
                 │
          ┌──────▼───────┐
          │ オーケストレーター │  タスク分解・計画・承認フロー管理
          └──┬────────┬──┘
             │        │
     ┌───────▼──┐  ┌──▼────────┐
     │ モデルルーター │  │ ツール実行層   │  許可リスト化されたコマンド/スクリプト
     ├──────────┤  ├───────────┤
     │ ローカル LLM │  │ サンドボックス  │  dry-run / 権限分離
     │ API モデル   │  └──┬────────┘
     └──────────┘     │
                   ┌──▼────────┐
                   │ 記録・監査層   │  行動ログ / システムログ / 実行結果
                   └──┬────────┘
                      │
                   ┌──▼────────┐
                   │ 知識ベース     │  過去の障害・手順書・サーバー構成情報
                   └───────────┘
```

## 各層の役割

| 層 | 役割 | 候補（未決） |
|---|---|---|
| インターフェース | 指示・質問・承認の受け口、通知 | CLI, Slack/Discord bot, Web UI |
| オーケストレーター | 依頼をタスクに分解し、承認が必要な手順で止める | 自作 / 既存エージェントフレームワーク |
| モデルルーター | タスクの種類・機密度でモデルを選ぶ | [model-strategy.md](model-strategy.md) |
| ツール実行層 | 実際にコマンドを叩く。許可リスト制 | MCP サーバー, 独自ツール定義 |
| 記録・監査層 | すべての入力・判断・実行・結果を保存 | journald, ファイル, SQLite, Loki 等 |
| 知識ベース | 過去事例やサーバー固有情報で回答精度を上げる | Markdown + 検索, ベクトル DB |

## 動作モード（案）

- **常駐モード**：定期実行（ログ要約、更新チェック、ヘルスチェック）
- **対話モード**：人間からの質問・依頼に応答
- **イベント駆動モード**：アラート受信をきっかけに調査を開始

## 配置

- エージェント本体をどこで動かすか（監視対象と同居 / 専用の管理サーバー）は未決
