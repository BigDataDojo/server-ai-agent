# 進め方

## 原則：コードを書く前に、設計を固める

まず何を作るのかを決め、どう作るかを設計書に書き、みんなでレビューしてから作る。設計がないと、途中で仕様が変わり、最初に目指したものと違うものができ、内部を知っている人やドキュメントがばらばらで後から直せなくなる。3つ目は、属人化したインフラを引き継ぐときに起きる問題そのものである。

実装は一部のメンバーだけが行う。ほとんどのメンバーの仕事は、設計を一緒に考えることと、そのための調査・検証である。

## 最初の2週間：共通基礎（コース選択の前に）

- インフラ構成図の説明を受ける
- 遊び用の LXC に SSH して触ってみる
- LLM の API を1回叩いてみる
- RAG（検索して、見つけた文書を元に生成する）の仕組みを知る
- git と Pull Request の練習

目安は MTG 1時間＋週2〜3時間（仮置き。状況を見て調整する）。

## 週次 MTG（1時間）：報告の場ではなく、決定の場

| 時間 | 内容 |
| --- | --- |
| 5分 | 各自1文で「進んだこと／詰まっていること」 |
| 35分 | 今週の問いを1〜2個決める。担当者が PR で出した「選択肢2〜3つ＋推奨」を元に議論し、採用を決めて理由を記録する |
| 15分 | 短い講義かデモ（最初は Sage、慣れたら学生が持ち回りで「今週学んだ技術を5分で教える」） |
| 5分 | 来週の「問い」と担当を決める |

MTG で「調べてきたことを順番に発表する」ことはしない。調べたことは事前に PR に書いておき、MTG ではそれを見て「どれを採用するか」を決めることに時間を使う。調べ物は、問いに答えるためだけに行う。

議事録は [notes/meetings/](../notes/meetings/) に書く。決定の理由は PR と決定記録に残るので、議事録には結論とリンクを並べるだけでよい。

## 設計書の出し方：問い → PR → MTG → マージ

```
Issue「今週の問い」を立てる（担当、コースのラベル、節目の Milestone）
   │
   ▼
担当者がブランチを切り、決定記録を書いて PR を出す（木曜まで）
   │   本文に「Closes #<問いの番号>」、レビュー依頼に @BigDataDojo/server-agent-founders
   ▼
レビュー担当が非同期でコメントする（金曜まで）
   │
   ▼
火曜の MTG で採用か却下かを決める
   │
   ▼
決定と理由を決定記録に書き、「採用」なら現在の構成（README.md）も書き換えてマージ
   → Issue が自動で閉じ、Projects のボードも更新される
```

- **main に直接 push しない。マージするのは、立ち上げメンバーが承認し、MTG で決まった PR だけ。** いまの GitHub のプランではこれを機械的に止められないため、「main の見張り」（Actions）が違反を見つけると、立ち上げメンバーを呼ぶ Issue を立てる
- 決定記録のテンプレートは [design/templates/decision.md](../design/templates/decision.md)
- **却下になった提案も、状態を「却下」にしてマージする。** 選ばなかった理由を残し、同じ議論を繰り返さないため
- 同じ問いに何人かが別々の PR を出してもよい。採用されなかった方は「却下」としてマージする
- 設計書の PR に、`notes/` の変更を混ぜない

## 調査メモの出し方

PR は要らない。`notes/<自分の GitHub ID>` ブランチに push すると自動で main に入る。詳しくは [notes/README.md](../notes/README.md)。

## 本番サーバーでの作業

本番のサーバーには触ってよい。ただし、エージェントと同じルールに従う。本番に触らないと学びにならず、次の鯖缶が育たないからである。

- まず各自に **遊び用の LXC** を渡す。好きに壊して構わない
- 本番は「Sage と一緒に」「予定した時間に」「事前に作業計画（何を・なぜ・戻し方）を書いてから」行う
- 作業後は、**エージェントに課すのと同じ形式の作業レポート**（目的、手順ごとのコマンドと設定、結果）を書く。人がエージェントの手本になる
- SSH の鍵は配らず、Cloudflare Access で入る
- パスワード・鍵・トークンは GitHub に書かない
- 評価に使う Slack ログは、名前・IP・ホスト名を伏せてから保存する

権限レベル（L0〜L3）は [design/00-overview](../design/00-overview/README.md#権限レベル人にもエージェントにも同じ区分) を参照する。
